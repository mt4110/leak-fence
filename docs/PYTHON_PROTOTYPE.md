# LeakFence — APIから出るデータの許可契約

状態: v0.1 実験用プロトタイプ。独立監査・本番負荷試験は未実施。
Python 3.12以上 / 実行時の外部依存なし / MIT。

## 目的

「侵入されない」だけでなく、アプリケーションが返そうとしたデータを
送信直前に再検査する。対象は、認証済みAPIの平坦なJSONレコード。
最強・完全防御という保証はしない。

## 現在止めるもの

- 信頼する認証・認可コンテキストがないHTTPリクエスト。
- ポリシー未設定のメソッド・パス。
- 他テナントのレコード、明示的に許可されていないレコードID。
- 許可リストにない項目、入れ子のオブジェクト・配列。
- 1応答あたりの件数・バイト数の上限超過。
- 重複JSONキー、不正UTF-8、非有限数、壊れたJSON。
- 検査を完了していない応答、圧縮済み応答、トレーラー、WebSocket。

ヘッダーを含め、検査完了まで応答を転送しない。
成功時もcontent-type等の固定ヘッダーのみを生成する。
Cookie・任意のヘッダーは通さない。遮断時は内容を含まない固定403を返す。
アプリ処理は標準で5秒で打ち切る（協調的なasyncキャンセルに依存）。
本実装はアプリ応答内容・本人情報をログに記録しない。

## 実行

```sh
python3 -m unittest discover -s tests -v
```

## 組み込み例

```python
from leakfence import Context, Guard, Policy

guarded_app = Guard(api_app, {
    ("GET", "/customers"): Policy(
        permission="customer:read",
        fields=frozenset({"id", "tenant_id", "name"}),
        max_records=100,
        max_bytes=262144,
    )
})

# 外側の信頼できる認証・認可層で、ユーザーと各レコードの権限を確認。
# 以下は説明用の固定値。実際はサーバー側の権限判定結果を使用する。
scope["leakfence.context"] = Context(
    principal="alice",
    tenant="acme",
    permission="customer:read",
    record_ids=frozenset({"customer-001"}),
)
await guarded_app(scope, receive, send)
```

応答例: `[{"id":"customer-001","tenant_id":"acme","name":"sample"}]`

クライアントのヘッダー・クエリ・JSONからContextを直接生成してはいけない。
所属・権限・レコードIDの許可は既存のサーバー側認可で確定する。
LeakFenceはその判定を応答に対して再適用する部品であり、認可エンジンではない。
IDは文字列、応答は平坦なレコードまたはその配列に限定する。
空配列は許可する。所属・ID以外の許可項目は省略可能。

## 配置

信頼できる認証・認可層 → LeakFence → APIアプリ。
ASGIサーバーは別途必要。ここにはサーバーや認証機構を同梱していない。
圧縮は検査の後でのみ行う。外側で追加するヘッダーやレスポンス変更は
この防壁の検査対象外。ログイン・ファイル配信・HTML・SSEは別サービスに分離。
未設定パスはヘルスチェックも遮断する。ルートの完全一致に注意する。

## 防げないもの

- 直接DB・バックアップ・オブジェクトストレージ・別の出口を使う持ち出し。
- ホスト侵害、悪意あるアプリコードによる回避、認証・認可層の侵害や誤判定。
- 許可済み項目の値に紛れた秘密・個人情報。意味解析やPII検知は未実装。
- 同じ所属内で誤って許可されたレコード、誤った許可項目の設定。
- 正常に見える少量の応答を繰り返す大量取得。累積取得予算は未実装。
- 暗号化・符号化による隠蔽、SQLインジェクション、パスワードリスト攻撃。
- アプリケーションの副作用、HTTP以外の通信、キャンセルを無視する処理。
- 同時接続数に比例するメモリ消費。接続数・CPU・受信量制限はサーバー側で必要。

本番の個人情報を守る用途では単独導入せず、独立レビューと負荷試験が必要。
最近の特定の漏えい事案を、この実装で防げたと主張する根拠はない。

## 次の実装順序

1. 認証済み主体ごとの累積取得予算。複数プロセス間で原子的に判定する。
2. 日本語PIIの検出。電話番号等の誤検知・見逃しを評価し、許可項目内も検査する。
3. 外向き通信の宛先制限。別プロセス・ネットワーク境界で迂回を防ぐ。
4. 値を残さない監査イベント、ポリシーの変更監査。
5. 独立セキュリティレビュー、プロトコルのファジング、実ASGIサーバー検証。
