# LeakFenceの信頼境界と保証の範囲

初期版は、正しく動作する認証・認可層と、送信する応答を必ずLeakFenceへ通すサーバーコードを信頼する。
攻撃者は正規の低権限アカウントを使い、要求を並行送信・再送し、対象IDを変えられると仮定する。
漏洩をゼロにする保証ではなく、定義した返却契約に違反する応答を停止するための部品である。

## 入力と検査

Contextのprincipal・tenant・permission・record_idsはサーバー側の認可結果から取得する。
クライアントヘッダーを転記したり、無制限なDB検索結果のIDから許可集合を作ったりしない。
contractもサーバーのメソッド・ルート設定で選ぶ。アプリが権限を検査して必要な行だけ取得する処理を維持する。
本人を認証済みでも、他人の行を返す権限があるとは限らない。

検査対象はUTF-8の平坦なJSONレコードまたはその配列。各レコードのテナント・ID・許可項目を検査する。
重複JSONキー、入れ子、非JSON値、件数・バイト数上限超過を拒否する。
フィールドの値の意味や出所は判定しない。許可されたnameに秘密が入るケースをテストで明示している。
空配列は許可するが、バイト数は消費する。重複行も返すたびに件数を消費する。

## 取得枠

Durable Objectはtenant・principal・budget_groupのJSONタプルから識別する。
ルートが違っても同じbudget_groupを指定すれば枠を共有する。権限やトークン文字列は枠のキーにしない。
グループ内で上限が異なる設定、重複contract、未設定contractを拒否する。
SQLiteの単一UPSERTが件数とバイト数を同時に条件判定し、永続化完了を待ってから応答する。
枠が不足する応答は全体を拒否し、許可した一部だけを送ることはない。

期間はUTC暦日。00:00 UTC（09:00 JST）で更新する。任意の連続24時間の上限ではなく、
日付境界をまたぐ短い時間には2日分を取得できる。次の日になってから古い日へ戻る要求は拒否する。
永続データは各Objectに1行。起動・再デプロイで使用量を初期化しない。
ただしnamespace変更、budget_groupや主体ID変更、管理者によるストレージ復元・改変は保証の外。
上限変更だけでは使用量をリセットしない。上限を使い切った利用者は翌日まで対象データを取得できない。
同一テナント内の別利用者には別枠がある。組織全体の総量制御・複数アカウントを使った分散取得の検知は未実装。

応答ロスト、タイムアウト、切断後は取得枠を自動で戻さない。実際より多く計上することがある。
再試行にも枠を適用する。これは課金メーターではなく、送信を許可するための保守的な消費量である。

## 失敗時と配置

サービスは既定で停止し、workers.dev・preview URLを無効にする。公開ルートを設定しない。
同じ利用者のCloudflareアカウント内のService Bindingからだけ呼び出す。
Service Bindingが呼出元の利用者認証を代行することはない。呼出元が正しく認可し、Contextを生成する必要がある。
アプリは返されたResponseをそのまま返す。検査後の追加データ・Cookie・任意ヘッダーは本検査の外。
ガードへ渡す前のデータをキャッシュから直接返す経路、エラー経路、代替APIも適用漏れとして点検する。

検査完了と枠確定まで本文を返さない。全処理は5秒でタイムアウトし、判定不能なら503を返す。
契約違反は403、枠不足は429。非対応の入力・パスは拒否し、元の応答へのフォールバックをしない。
アプリ本体の副作用を取り消せないので、読み取り専用APIから導入する。
一回消費型GET、決済、状態更新、ファイル配信、HTML、SSE、WebSocketは初期版の対象外。
Rust側はレスポンス全体をバッファリングする。最大本文256KiBに加え、エンベロープ・パース結果・複製のメモリが必要。
WorkersのCPU・メモリ・リクエスト制限や前段の悪用対策を代替しない。

## データとログ

アプリの本文・トークン・許可ID一覧を保存・独自ログ出力しない。DO識別には不透明な主体ID等を使用する。
保存するのは日・件数・バイト数。エラーは固定コードだけにする。
Cloudflareは応答処理の実行基盤であり、Cloudflareにもデータを渡さない構成ではない。
プラットフォーム、呼出元、監視基盤のログとデータ所在は利用者が別途確認する。
デモと試験の.localディレクトリには合成データの状態が残る。利用者の既存DBは使わない。

## 対応しない侵害

ホスト・認可層・アプリコードの侵害、DBへの直接アクセス、バックアップ・ログからの取得、
許可フィールドの値を使う隠蔽、既知CVEの修正、盗難管理者権限の真偽判定は行わない。
管理者が広い権限を設定すればその範囲を許可する。総合DLP・WAF・EDRではない。
正規の少量取得や、API以外の経路を通る持ち出しは残る。
