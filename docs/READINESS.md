# 実用化の条件

2026-10-14更新。標準導線は、既存の認証・認可を持つCloudflare Workerの、成功時に200の平坦JSONを返す読み取り専用GETルート1本です。
対象は返却時の越境・余計な項目の返却・取得量超過。現在の目的は導入者の確保と継続利用で、機能数や価格の確定を優先しません。
対応範囲・優先順位・終了条件は [マイルストーン](MILESTONES.md)、接続手順は [QUICKSTART](QUICKSTART.md) を参照してください。
すべての漏洩を防げないことは、セキュリティツールとしての価値がないことを意味しません。
防御する経路、成立に必要な前提、導入者が確かめられる証拠を揃えることを実用化の条件にします。
現時点で安定版や独立監査済みの製品へ昇格したとは扱いません。

## どの事故を止めるか

| 事故 | 対策と前提 |
| --- | --- |
| 正規利用者の要求へ別テナントの行が混ざる | サーバーが認可した所属と、返却レコードの所属を照合して応答全体を拒否 |
| 同じテナントの他人のレコードが混ざる | 認可処理が独立して確定した許可ID集合と照合して拒否 |
| DBの項目追加などで秘密の列を返してしまう | 許可項目の一覧にないキーを拒否。許可キーの値に混ざった秘密は判定しない |
| 認証済み利用者が取得枠以上を要求する | 同じテナント・主体・グループの永続取得枠を送信前に確定。別主体・別経路の相関は未実装 |
| 検査・保存・接続が失敗する | 元データへフォールバックせず対象応答を停止。稼働可否への影響は運用で判断 |

APIのオブジェクト・項目の認可不備は、[OWASP API1:2023](https://owasp.org/API-Security/editions/2023/en/0xa1-broken-object-level-authorization/)と
[API3:2023](https://owasp.org/API-Security/editions/2023/en/0xa3-broken-object-property-level-authorization/)が扱うリスクです。
LeakFenceは認可基盤を代行しません。呼出元が正しく認可した結果を、実際の応答へ再適用する位置づけです。
個別の公表された漏洩事件を防げたと推測したり、事故全体への防止率を計算したりしません。

## 実装済みの導入部品

- 同じRust検査コードを使うCLI：合成デモ、契約の検証、手元の応答の内容検査。データ送信・保存・本文出力なし。
- 認可から検査までをまとめたGET用接続関数：認可前にデータを読まず、認可結果を固定し、例外は固定503。
- ガード呼出しの期限：中断を無視するBindingでも接続関数側で503へ戻す。元データを返さない。
- 一つのルートの接続例と、日本語の導入ガイド。未保護の応答を返す例を標準接続例へ含めない。
- CLIの終了コード・出力、接続関数の失敗時、実Wasm/SQLiteを使う接続と並行取得の回帰試験。

部品の2026-10-09時点の検証は [導入改善のローカル検証](VALIDATION_ADOPTION_2026-10-09.md) を参照してください。後続の [ZT Gateway接続検証](ZT_GATEWAY_RESULTS_2026-10-10.md) はGoの実製品ハンドラーを使った所有者による限定試験で、標準導線の第三者導入や本番採用とは区別します。

これらは導入をしやすくするための実装であり、第三者が説明だけで導入できた証拠はまだありません。
`readJson`内のDB問い合わせや認可処理の時間・キャンセルは呼出元の責務です。
ガードの5秒・接続関数の6秒という時間制限は、認可とDB読み取りまで含めた全APIの時間保証ではありません。

## 開発版から本番の判断へ

| 必要な証拠 | 状態・次の作業 |
| --- | --- |
| コアの拒否条件、並行取得、再起動後の取得枠、設定失敗 | ローカル試験あり。実装に応じて回帰試験を維持 |
| 実Cloudflareへの接続 | 専用の合成APIで限定試験済み。[条件と結果](STAGING_RESULTS_2026-10-09.md) |
| 既存製品の一つの読み取りAPIへの接続 | ZT Gatewayの要約GETで、実Go/DBと合成データによる限定検証済み。標準Workers導線の実アプリ・GETパスは未指定 |
| 適用漏れと認可設定の確認 | ZTの専用入口では直接アクセス・未認証・内部ヘッダー等を限定検証済み。新しい導入先ではキャッシュ、別ルート、エラー、直接DBアクセスを別途点検 |
| 対象APIの業務量に基づく取得枠・遅延・原価 | 未確定。既存SLO、正常業務、固定費を含む費用目標と比較 |
| 実際のネットワーク・永続化障害、長時間・対象地域の負荷、停止復旧 | ZT検証環境の停止・入口閉鎖の記録あり。実基盤障害・長時間負荷・標準導線の常設復旧は未検証。例外注入と区別する |
| 導入者から独立したセキュリティレビュー | 未実施。対象コミット・認可設定・接続経路を含めてレビュー |
| 第三者がガイドだけで導入できること | 未確認。詰まった箇所、所要時間、誤拒否、継続利用の意思を記録 |
| バージョン配布と保守 | npm/crates.ioの配布、安定版のサポート範囲・期間は未確定 |

次は、標準導線に採用する実アプリとGETパス、独立した許可IDの判定元、正常応答の契約を固定します。既存のZT接続を未実施としてやり直すのではなく、標準Workers導線の導入・点検キットを完成させる区切りです。
それが済むまで、eBPF・AI検知・決済など別の機能を追加して守備範囲を広げません。
既存の認可・DTO・DB制約だけで十分な場合や、導入・運用負担が防げる危険に見合わない場合は、
継続開発を保留し、検査部品として公開した成果を残します。

## 説明と販売

GitHubの短い説明では、対象となる事故と導入形態を先に示します。
開発段階・未監査・対象外はREADME、Security Policy、本番採用の条件から確認できるようにします。
安定性の裏付けを増やす前に、保証を強めたり「すべての漏洩を防ぐ」を売り文句にしたりしません。

無料のコア防御を維持し、有償候補は環境間の設定配布・変更レビュー・保守等とします。
継続利用と支払意思が確認できる前に価格を確定しません。従量の取得枠を課金メーターへ転用しません。
この段階では機能数より、一つの現場で防御が有効になる導入手順を優先します。
