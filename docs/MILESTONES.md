# 標準GET導入のマイルストーン

Updated: 2026-10-14
Status: M0の設計・文書。実装・配置・本番採用の完了記録ではない。

## 主目的と標準対象

利用者が自分のAPIのGETルート1本へ導入し、次の変更でも点検・運用できることを優先する。
対象は、既存の認証・認可を持ち、成功時に200の平坦JSONレコードまたは配列を返すCloudflare Worker。
LeakFenceは既存認可を代行せず、許可項目の値に秘密が混ざったかを分類しない。

接続は、認可 → 許可範囲を固定 → 読取り → 非公開Service Binding → 検査・永続取得枠確定 → 応答。
失敗時に元本文へ戻さない。全API、全キャッシュ、DB・バックアップへの直接アクセスの保護とは扱わない。

参照例は [GET /v1/customers](../examples/integration/customer-api.ts)。実アプリ・GETパス・業務設定は未指定。
[QUICKSTART](QUICKSTART.md)の契約表をその導入先について埋める。サンプルの取得枠を本番値にしない。

## 大きな残課題と優先順位

| 優先度 | 課題 | 区切り |
| --- | --- | --- |
| P0 | 対象GET、認可の根拠、返却契約、取得枠、迂回経路を固定 | M0の共通契約と、M1の実導入先の契約。許可IDを未検査の応答から作らない |
| P1 | 正常応答を崩さない導入・点検キット | M1。HTTP Responseの自動変換ではないこと、ステータス・Cookie・必要ヘッダー・キャッシュの扱いを判断 |
| P1 | 認可・読取りを含む期限、停止・復旧、枠保持 | M2。接続関数のガード呼出し期限6秒だけで全APIの期限としない。例外注入と実基盤障害を区別 |
| P1 | 業務に合う取得枠、追加遅延、実使用量 | M2。再試行・UTC日付境界・誤拒否を含め、既存SLOと費用条件で判断 |
| P2 | 版固定、更新、配布・保守、外部案内 | M3。npm/crates.ioや新サイトを先に必須化しない |
| 本番採用前 | 独立レビューと本番条件での確認 | M3後も別ゲート。開発版の案内を安定版・監査済みという保証へ変えない |

## M0 — 標準導入契約を一本化する

成果物：このマイルストーン、[READINESS](READINESS.md)の現状分類、QUICKSTARTの契約・受入条件。

終了条件：

- 対象をWorkersの平坦JSON GET1本に限定し、認可・応答・取得枠・迂回・失敗時の責務がコードと一致する。
- 実装済み、限定検証済み、未確認を分け、旧資料の「未実施」を現在の全実績と混同しない。
- 実際の導入アプリ・GETパスが未指定であることを残す。契約の例を実導入成功として扱わない。
- 差分と文書リンクの軽量確認を通す。文書の完了はruntime・本番・第三者導入の成功ではない。

## M1 — 実GETルート1本の導入・点検キット

成果物：選定したアプリとパスの契約、固定版adapter/設定、短い接続手順、合成データによる受入記録。
既存adapterと接続例を優先し、足りない箇所だけを変更する。

開始条件：導入先と権限・応答の根拠が指定され、Cookie等の非対応条件がないか判断できること。

終了条件：

- 既存の認証・認可と読取りを接続し、正常本文と期待するHTTP契約を比較する。
- 未認証・認可拒否・非GET、越境・許可外ID・項目、枠境界・並行取得、設定/接続/読取り異常を確認する。
- キャッシュ・別ルート・直接入口・例外経路を列挙し、検査を通らない経路を保護済みと表示しない。
- 導入の手順・変更ファイル・詰まった箇所を記録する。顧客本文・実トークン・秘密鍵は収集/添付しない。
- 本文は合成マーカーで試験中に照合し、共有する記録はケースID、期待/実際、判定、実行条件に限定する。

## M2 — 運用の成立を確認する

成果物：全GETの期限、停止・復旧、業務上の取得枠、同条件の比較時間・基盤使用量の記録。

終了条件：

- 認可・DB読取りの時間とキャンセルを含めて定義する。停止時は本文を返さない。
- 同じDO namespace・主体ID・budget_groupで停止/復帰・更新し、消費済み枠を保持する。
- 正常業務、再試行、UTC暦日境界の消費を説明できる。月額費用の強制上限とは扱わない。
- 比較対象・入力・地域・並行数・試行数を揃え、途中結果を保存する。少量の最大値をp99と呼ばない。
- 欠けた使用量・請求値をゼロ扱いせず、既存SLOと合意した費用条件から継続/保留を判断する。

Cloudflareへの配置・公開入口・負荷試験は、対象環境、要求上限、停止方法、費用条件を具体化して別途承認を得る。

## M3 — 外部へ案内できる開発版

成果物：対応範囲、版の固定・更新・ロールバック方法、導入ガイド、問い合わせ先、未確認事項。

終了条件：

- README、ガイド、設定例、実装が一致し、取得からM1の点検までを辿れる。
- 第三者が試せる説明になっていることと、第三者の導入成功・継続利用を確認したことを分ける。
- 独立レビュー・実基盤障害・長時間負荷・本番採用の判断が残ることを明示する。
- GitHub Release、パッケージ公開、広告・連絡・本番反映はそれぞれ明示承認後に行う。

## 保留・終了条件

入れ子/任意形式、書込み/一回消費型API、全APIの自動発見、別言語SDK、GUI、AI検知、eBPF、決済、汎用テレメトリーはこの区切りへ追加しない。
既存の認可・DTO・DB制約だけで十分な場合、または導入負担・遅延・誤拒否が防げる事故に見合わない場合は拡張を保留する。
その場合も既存コード・証拠は保持し、削除や枠リセットを終了の条件にしない。
