# 初期実装の検証記録

2026-10-08時点。入力は合成データのみ。Cloudflareへのデプロイ・実顧客データの利用は行っていない。
2026-10-09の専用Cloudflare環境での接続検証は[別の結果記録](STAGING_RESULTS_2026-10-09.md)を参照。

## 実施した範囲

- Rustコアの6試験：認可・テナント・ID・項目、JSONの曖昧さ、サイズ・設定、許可値中の秘密という限界。
- ローカルworkerdの7試験：実際のRust/WasmとSQLite-backed Durable Objectを使用。
  80件の並行要求に対し50件許可・30件拒否、別主体の枠分離、プロセス再生成後の使用量維持、
  同一グループの別契約による迂回拒否、初回からのバイト数上限、設定・binding不備の拒否を確認。
- SQLiteの4試験：上限一致、拒否時の消費量維持、日付更新・巻き戻し、上限引下げ。
- 保全したPython試作の12回帰試験。
- Rustのformat・Clippy、TypeScript接続関数の型検査、Wasm releaseビルド。
- npm auditとCargo.lockのRustSec照合。照合時点で既知の脆弱性は報告されなかった。

試験基盤の初期設定で、Miniflare 5の変換器が旧modulesRulesを受け付けず、旧永続化設定を引き継がない問題を検出。
Wasmモジュールを明示しresourcePersistencePathへ設定を修正した。並行試験では応答本文を各要求完了時に読み取り、
全許可応答の本文一致と全拒否応答の本文非包含を検証する。失敗を除外したり上限の期待値を下げたりしていない。

## 未実施

実APIとの接続、第三者による導入、性能・原価・支払意思の測定は未実施。
